# DESIGN-028: Memory rescue and fights that matter

- **Status:** September 29 child playtest correction; implementation contract.
- **Source:** Tom's portrait phone screenshot and report: the large Age 0 memory would not collect, Attack appeared to do no damage while Bash did, enemies were sparse and could be run past, and combat looked like swirls.
- **Supersedes:** DESIGN-018's direction to follow the path back from the large memory when a little memory was missed, and its ordinary-independent boss rule for new family template versions only. Existing frozen journeys keep their authored encounter plans.

## What failed

The large memory is released when its boss falls, but collection still requires both little memories. In the pictured Age 0 run the HUD shows only one of two. The route's slide is one-way: the player cannot jump from the party lawn back to the earlier balcony memory. The old "Follow the path back" hint points at an impossible route, and the saved post-boss checkpoint sends a fall or reload back to the same lawn.

Attack also looked usable before the route's tool was collected, although the server required that tool to deal damage. Bash used the separately collected shield and could hit at a longer range. The player saw an animated swing even when Attack could not hurt the target. An ordinary foe wakes at about 6 m and walks at 0.85 m/s while the player walks at 4 m/s; its windup takes 0.8 s. The player can cross its narrow reach before it attacks, and the current boss can be defeated without a single ordinary fight. The same spinning ring portrays Attack and Bash.

## Direction

Roblox's own [design guidance](https://create.roblox.com/docs/production/game-design/design-for-roblox) says younger players often enjoy exploration and experimentation, and that mobile games should reach fun quickly with visual UI. Its [core-loop example](https://create.roblox.com/docs/production/game-design/core-loops) links exploration, fighting and upgrades in an action RPG. [Onboarding guidance](https://create.roblox.com/docs/production/game-design/onboarding-techniques) calls for visible hit, health and reward feedback. The [2025 Replay](https://about.roblox.com/newsroom/2025/12/roblox-replay-decoded-search-style) shows a wide mix of searched roleplay, simulation, survival and combat experiences. These are platform patterns, **not evidence of which games Tom's children prefer**. This game will borrow the useful loop and feedback principles without copying a specific Roblox game's characters or progression.

1. The first thumb press of Attack must be useful. On route-memory chapters, an unarmed basic hit deals one authoritative damage when in range; collecting the chapter tool still upgrades it to the planned damage. Bash keeps its separate shield role. Primary and Bash get separate, brief forward strike shapes rather than a shared spinning ring. Keep the immediate swing and sound, while a visible damage number appears only when the server confirms a lower enemy HP. Show the selected foe's health at the screen edge so a child can tell whether the press worked. Retain readable windups and the existing safe HP/damage budget.
2. Make existing foes matter to current saved runs by tuning bounded pursuit and anticipation, with an avoidable telegraphed strike. Do not raise later enemy damage just to punish running: two existing later hits can already defeat a ten-HP player. Preserve authored arenas, platform height checks, exits and checkpoint safety. A new family template version may place more foes on validated decks; do not rewrite a frozen save to add them.
3. On new family template versions, place at least six ordinary encounters per chapter where the geometry supports safe arenas. Two ordinary wins from any eligible encounters unlock that chapter's boss; the remaining foes and bonus slots stay optional. Show the two-win objective in the game UI and distinguish a locked boss from a missed hit. A one-way slide can strand a child beyond foes they skipped, so a locked boss must offer a visible return to chapter start that keeps HP, collected items, memories and finished fights. Earlier publication versions keep their original boss rule. Do not make a specific foe mandatory or create a post-boss memory softlock.
4. After a boss victory, a player missing a little memory gets one visible **Find memory** control. It returns them locally to the missing memory's validated checkpoint, clears held input, and preserves their server save. Falls and reloads in that state use the same checkpoint. Once both little memories are recovered, the control changes to **Big memory** and returns the player near the reward. The large memory remains visible but must clearly explain that it needs both little memories when approached. The return is available to existing frozen runs, including Age 0.

## Acceptance

- Reproduce the exact Age 0 one-way-slide case with a missed first minor, boss victory, reload/fall, return, missing pickup and big-memory collection. Verify progress, photos and server revision are never erased by a local return.
- With no weapon, Attack reduces a valid ordinary target by one HP; Bash remains independent. A weapon upgrade uses its frozen damage. Out-of-range/failed requests do not display a confirmed damage number.
- Verify a straight runner meets a visible, avoidable threat in existing worlds, and the new template's two-win boss objective cannot be bypassed. Run past every foe in A1, take its one-way slide to the locked boss, use Return to start, win two fights and reopen the boss without losing progress. Exercise defeat/retry, safe decks and both family worlds in synthetic play. Test the portrait controls and visual strike direction in a real browser. Child-on-device feel still requires play with Tom's children after deployment.
- Keep old template files, frozen plans, private photos and started progress unchanged. Publishing a newer template offers updated worlds for future runs; it does not silently restart an existing child's journey.
